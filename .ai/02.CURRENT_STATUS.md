# Project Status

## Overall Status

The Enrollment Domain Discovery is closed and the AUDIT-001 documentation reconstruction is technically approved as the official Enrollment baseline.

E004.1 — Identity & Access Baseline is completed and merged into `main` through PR #3.

E005 — Person Baseline is the current functional milestone. Phase 1 established ADR-0018 and the pre-production rebaseline boundary. Phase 2 completed the IdentityAccess persistence alignment, the general schema rebaseline and the retirement of incompatible legacy Person/Family flows.

Phase 3A implements the approved Person Domain as an isolated Aggregate Root with its documented Value Objects and invariants. Phase 3B now adds the minimal Person Repository contract, its PDO implementation and local persistence coverage. No application, HTTP or UI layer is included.

IdentityAccess persistence now targets the official `users` structure without `deleted_at` or `locked_until`. Its domain, application, HTTP, session, CSRF and authentication behavior remain unchanged.

## Repository Status

- PR #3 was merged into `main` at commit `60a444d`.
- E004.1 remains functionally unchanged.
- IdentityAccess persistence and its tests remain aligned with the official `users` columns.
- Migrations 002–009 now define the clean 36-table functional baseline; migration 001 and the runner-owned `migrations` table remain technical metadata.
- Legacy Person/Family controllers, services, repositories, views and routes incompatible with the approved model were retired pending their milestone implementations.
- Seeders now provide only approved status types and statuses. No institutional catalog value or synthetic Person is invented; optional administrator creation requires an existing Person identifier and an external initial password.
- Local PHP, Composer, schema-parity, application-bootstrap, IdentityAccess, Person Persistence and HTTP validations passed. No migration or database operation was executed.
- Person Domain now contains only the Person Aggregate Root, PersonId, PersonalName, Identification, ContactInformation, GENERAL_STATUS lifecycle and domain exceptions.
- Person unit tests cover valid construction, optional identity/contact data, Value Object equality, invalid formats and bounds, non-future birth date, Catalog references, atomic identity replacement, contact replacement and activation lifecycle.
- PersonRepository exposes only lookup by PersonId, lookup by Identification and save. PdoPersonRepository maps every approved `persons` column, validates GENERAL_STATUS, preserves nullable fields, inserts new Persons through database-generated AUTO_INCREMENT identities and performs exact-row updates.
- Local persistence tests cover complete reconstruction, present and absent parameterized identification lookups, optional fields, ACTIVE and INACTIVE, invalid status ownership/code, insertion, update, null removal, normalized identification uniqueness and a disappearing update target.
- MariaDB connections explicitly use `utf8mb4` with `utf8mb4_unicode_ci`. Person identification lookup compares the bare indexed `identification_key` with one prepared key parameter instead of constructing a connection-collated SQL expression.
- The disposable MariaDB harness now includes real Person insert, ID and identification lookup, update, GENERAL_STATUS mapping, normalized uniqueness, connection/column collation verification, safe collation diagnostics and cleanup coverage without institutional seed data.
- No Person use case, DTO, application service, controller, HTTP route or view exists in Phase 3B.
- GitHub remains the single source of truth.
