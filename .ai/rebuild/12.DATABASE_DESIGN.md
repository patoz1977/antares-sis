# DATABASE DESIGN — Enrollment clean rebuild

## 1. Autoridad, motor y convenciones
Implementación física MySQL 8 del modelo temporal `11.DOMAIN_MODEL.md`. Tablas/columnas en `snake_case`; PK `id BIGINT UNSIGNED AUTO_INCREMENT`; FKs `<singular>_id`; una base por institución, sin `institution_id`. Todas las entidades de dominio tienen `created_at`, `updated_at`, `deleted_at`, `created_by`, `updated_by`, `deleted_by` cuando aplica. Soft delete usa `deleted_at`; unicidad activa se implementa con columnas generadas STORED, nunca `UNIQUE(..., deleted_at)`.

## 2. Tipos, estados e integridad
VARCHAR para códigos/nombres/teléfonos, TEXT para observaciones/medicina, DATE para fechas, TIMESTAMP para lifecycle, DECIMAL(10,7) para geolocalización, TINYINT(1) para flags. Statuses usa `status_id`; Enrollment solo admite Draft, Submitted, Completed, Cancelled por reglas de dominio. FKs usan RESTRICT salvo hijos del snapshot, que usan CASCADE. Checks validan booleans y rangos de coordenadas.

## 4. Catálogos
Cada catálogo base tiene `id`, `code VARCHAR(50)`, `name VARCHAR(150)`, `description NULL`, `display_order`, `is_active`, auditoría y claves activas generadas para code/name. `cantons.province_id` FK y `parishes.canton_id` FK implementan Province→Canton→Parish. No existen genders, nationalities, blood_types ni transport_types.

## 5. Identity y roles
`persons`: id; document_type_id FK; document_number; first_name; middle_name NULL; first_surname; second_surname NULL; birth_date; sex_id FK; marital_status_id NULL FK; education_level_id NULL FK; email NULL; mobile_phone NULL; landline_phone NULL; status_id FK; auditoría. Generated `active_identification_key = IF(deleted_at IS NULL, CONCAT(document_type_id, ':', document_number), NULL)`; UNIQUE. Sin address.

`users`: id; person_id FK; username; password_hash; status_id FK; last_access_at NULL; locked_at NULL; auditoría; generated active person/username keys UNIQUE.

`representatives`: id; person_id FK; occupation NULL; company NULL; position NULL; work_phone NULL; work_email NULL; status_id FK; auditoría; generated active_person_key UNIQUE.

`students`: id; person_id FK; institutional_code; admission_date NULL; status_id FK; auditoría; generated active_person_key and active_institutional_code_key UNIQUE.

## 6. Family
`families`: id; display_name NULL; status_id FK; auditoría.

`family_representatives`: id; family_id FK; representative_id FK; relationship_type_id FK; is_primary; status_id FK; auditoría; generated active_family_representative_key and active_primary_family_key = IF(deleted_at IS NULL AND is_primary=1, family_id, NULL); both UNIQUE.

`family_students`: id; family_id FK; student_id FK; started_at TIMESTAMP NOT NULL; ended_at TIMESTAMP NULL; status_id FK; auditoría; `active_student_id BIGINT UNSIGNED GENERATED ALWAYS AS (IF(ended_at IS NULL AND deleted_at IS NULL, student_id, NULL)) STORED`; UNIQUE(family_id,student_id,started_at) and UNIQUE(active_student_id).

`family_addresses`: id; family_id FK; label; province_id FK; canton_id FK; parish_id FK; main_street; street_number NULL; secondary_street NULL; sector NULL; reference NULL; latitude NULL CHECK; longitude NULL CHECK; status_id FK; auditoría; generated active_family_label_key UNIQUE.

`representative_address_assignments`: id; family_address_id FK; family_id FK; representative_id FK; ended_at NULL; auditoría; `active_family_representative_key VARCHAR(42) GENERATED ALWAYS AS (IF(ended_at IS NULL AND deleted_at IS NULL, CONCAT(family_id, ':', representative_id), NULL)) STORED`; UNIQUE. FKs validate address, family and representative; transaction validates address belongs to family and active FamilyRepresentative.

`student_address_assignments`: id; family_address_id FK; family_id FK; student_id FK; ended_at NULL; auditoría; `active_family_student_key VARCHAR(42) GENERATED ALWAYS AS (IF(ended_at IS NULL AND deleted_at IS NULL, CONCAT(family_id, ':', student_id), NULL)) STORED`; UNIQUE. Transaction validates address and active FamilyStudent share family; this is deliberate cross-table integrity not expressible by one FK.

`family_emergency_contacts`: id; family_id FK; names; relationship_type_id FK; mobile_phone; phone NULL; email NULL; observations NULL; status_id FK; auditoría; no person_id. `emergency_contact_assignments`: id; family_emergency_contact_id FK; student_id FK; priority NULL; status_id FK; auditoría; generated active_contact_student_key UNIQUE; transaction validates same Family.

`family_authorized_pickups`: id; family_id FK; names; relationship_type_id FK; mobile_phone; phone NULL; document_number; observations NULL; status_id FK; auditoría; no person_id. `authorized_pickup_assignments`: id; family_authorized_pickup_id FK; student_id FK; status_id FK; auditoría; generated active_pickup_student_key UNIQUE; transaction validates same Family.

## 7. Enrollment y documentos
`enrollments`: id; student_id FK; family_id FK; academic_period_id FK; grade_id FK; section_id NULL FK; billing_responsible_name; billing_identification; billing_email NULL; billing_phone NULL; medical_information NULL; requires_institutional_transport; is_authorized_to_leave_alone; status_id FK; started_at; submitted_at NULL; completed_at NULL; cancelled_at NULL; auditoría; generated active_student_period_key UNIQUE.

`institutional_documents`: id; name; description NULL; status_id FK; auditoría. `institutional_document_versions`: id; institutional_document_id FK; version; file_reference; published_at; status_id FK; auditoría; generated active_document_version_key UNIQUE. `document_requirements`: id; institutional_document_version_id FK; academic_period_id FK; is_required; auditoría; generated active_requirement_key UNIQUE. `document_acceptances`: id; enrollment_id FK; institutional_document_version_id FK; accepted_by_representative_id FK; accepted_at; auditoría; generated active_acceptance_key UNIQUE.

`enrollment_submission_snapshots`: id; enrollment_id FK; submitted_by_representative_id FK; submitted_at; timestamps; generated active_enrollment_key UNIQUE. `submitted_address_snapshots`: snapshot FK; label; province_name; canton_name; parish_name; streets/reference. `submitted_emergency_contact_snapshots`: snapshot FK; names; relationship_name; phones/email; priority. `submitted_authorized_pickup_snapshots`: snapshot FK; names; relationship_name; phones; document_number. Snapshot child FKs use CASCADE; it stores no generic person/student/family data.

## 8. Índices y eliminación
Cada FK tiene índice. Las claves activas generadas anteriores son los índices de unicidad activa. Recursos asignados y documentos aceptados no se eliminan físicamente; se desactivan o se bloquean con RESTRICT. El reenvío reemplaza los hijos de snapshot dentro de la transacción de Enrollment.
