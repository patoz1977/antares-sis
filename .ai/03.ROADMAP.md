The roadmap represents the agreed direction of the project. It organizes future work without using planning sections as a status report or historical log.

# Development Workflow

Every future milestone shall follow the same lifecycle:

1. Business analysis.
2. Domain validation.
3. Technical design.
4. Implementation.
5. Testing.
6. Technical review.
7. Documentation update.
8. Commit.
9. Repository synchronization.

No milestone is complete until implementation and documentation are synchronized.

---

# Scope Management

During a milestone:

- no future functionality is incorporated;
- architectural changes require documented justification;
- undefined rules are not implemented;
- permanent project knowledge is recorded in the repository;
- database execution requires explicit authorization.

---

# Architectural Governance

- GitHub is the single source of truth.
- `.ai` contains the official project documentation.
- Approved architecture and domain decisions precede implementation.
- Business rules drive technical design.
- Long-term maintainability has priority over short-term speed.
- Compatibility is preserved whenever reasonably possible.

---

When a milestone changes state, review:

- `02.CURRENT_STATUS.md`;

# Quality Criteria

A planned milestone may be marked complete only when:

- its approved objective is achieved;
- required validation and tests pass;
- documentation is synchronized;
- architectural consistency is verified;
- repository changes are reviewed and confirmed.
