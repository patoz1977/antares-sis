## Purpose

This document is the official historical record of the project.

It records completed work in chronological order.

It intentionally excludes:

- the current status of the project (see `02.CURRENT_STATUS.md`);
- future planning (see `03.ROADMAP.md`).

This document is immutable except for the addition of new historical entries.

# Logging Rules

Every completed milestone shall generate a new entry.

Each entry should record:

- date;
- completed milestone;
- summary of the work performed;
- important architectural decisions;
- documentation updated;
- repository status.

Entries shall never be modified to reflect the current state of the project.

### Temporary User Lockout Policy

**Date:** 2026-07-31

**Milestone:** E004.1 — Identity & Access Baseline

**Status:** Documentary decision completed

#### Ambiguity

ADR-0013 required failed-attempt tracking and a temporary lock represented by `locked_at`, but the official documentation did not define the threshold, duration, expiration behavior or institutional configuration.

#### Decision

ADR-0016 approved a default threshold of five consecutive failed attempts and a default duration of fifteen minutes. Both values are configurable per deployment through a typed authentication policy. Attempts during an active lock do not extend it; expiration and successful authentication reset `failed_login_attempts` and `locked_at`; `USER_STATUS = DISABLED` remains independent.
