### Temporary User Lockout Policy

**Date:** 2026-07-31

**Milestone:** E004.1 — Identity & Access Baseline

**Status:** Documentary decision completed

#### Ambiguity

ADR-0013 required failed-attempt tracking and a temporary lock represented by `locked_at`, but the official documentation did not define the threshold, duration, expiration behavior or institutional configuration.

#### Decision

ADR-0016 approved a default threshold of five consecutive failed attempts and a default duration of fifteen minutes. Both values are configurable per deployment through a typed authentication policy. Attempts during an active lock do not extend it; expiration and successful authentication reset `failed_login_attempts` and `locked_at`; `USER_STATUS = DISABLED` remains independent.

### MVP Session Inactivity Policy

**Date:** 2026-07-31

**Milestone:** E004.1 — Identity & Access Baseline

**Status:** Documentary decision completed; technical corrections continue

#### Review Finding

The formal review of PR #3 identified that the general Security Guidelines required automatic session expiration by inactivity while E004.1 did not define or implement an approved inactivity policy.

#### Decision

ADR-0017 establishes that sessions do not expire automatically by inactivity during the MVP. Explicit logout, session identifier regeneration after login and complete session destruction during logout remain mandatory. A future configurable policy is outside E004.1, disabled by default and requires a separately approved milestone.

ADR-0017 does not modify ADR-0016 or the temporary User lockout policy.

### E005 Person Baseline — Phase 3B MariaDB Collation Alignment

**Date:** 2026-08-01

**Milestone:** E005 — Person Baseline

**Status:** MariaDB collation correction implemented locally; physical validation pending; E005 remains in progress

#### Result

- Diagnosed the Person identification lookup failure as a session/expression collation mismatch: the approved `persons` columns inherit `utf8mb4_unicode_ci`, while MariaDB 10.4 supplied `utf8mb4_general_ci` to the parameter-built expression because the PDO session declared only the character set.
- ConnectionFactory now establishes `utf8mb4` with `utf8mb4_unicode_ci` explicitly for MariaDB connections while preserving the UTC session convention.
- PdoPersonRepository compares the bare indexed `identification_key` with one prepared key parameter; no function or query-specific COLLATE is applied to the indexed column.
- Local SQLite coverage verifies case/space normalization, quoted values, prepared lookup shape and unchanged normalized uniqueness. The accumulated local suite contains 67 passing tests plus the existing HTTP/session scenarios.
- The disposable MariaDB harness verifies the session character set/collation and reports both session values plus the collations of `persons.document_number` and `persons.identification_key` if a collation error occurs, without exposing credentials.
- `composer test:mariadb` was not executed; no database connection, migration or UEAnt access occurred. Physical XAMPP validation remains pending and the phase is not approved.
